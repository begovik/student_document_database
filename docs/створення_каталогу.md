# Створення каталогу літератури за спеціальністю

## Передумова

Мета — мати можливість швидко знайти в існуючій базі даних документи, що
відповідають конкретній спеціальності (наприклад, «076 Підприємництво, торгівля
та біржова діяльність»), та сформувати каталог придатних для студентських робіт
джерел (курсові, магістерські, контрольні, звіти з практики).

**Важливо:** каталог базується виключно на реальних документах, зібраних
системою. Ніякої LLM-генерації чи вигаданих джерел.

## Що вже є

- Таблиця `topics` (25 тем з УДК-префіксами та ключовими словами)
- Таблиця `document_topics` (38 307 класифікованих документів)
- Класифікатор: УДК (0.45) + ключові слова (0.15) + LLM Gemini (0.40)
- `search_queries` — 250 згенерованих пошукових запитів по темах
- CLI `export` — експорт документів за статусом та мовою (але без фільтру за
  темою/УДК)
- CLI `db-status` — стан БД, outbox, дзеркало

## Чого не вистачає

1. **Топік `trade` у таксономії** — документи з УДК 334.7/339.1/336.76
   класифікуються як `econ` (УДК 33 — ширший префікс). Немає можливості
   шукати за темою «Підприємництво, торгівля та біржова діяльність».

2. **CLI-команда каталогу** — `export` не фільтрує за темою чи УДК. Немає
   команди типу `harvester catalog --topic trade`.

3. **Якість метаданих** — 74% записів trade-тематики не мають title. Для
   каталогу потрібні повні метадані (title + authors + year + url).

4. **Різноманітність типів** — серед trade UDC лише статті та одна теза.
   Підручники, монографії, методички відсутні (або не мають trade UDC).

5. **Класифікація існуючих документів** — після додавання топіку `trade`
   потрібна міграція: INSERT INTO document_topics для вже зібраних документів
   з відповідними УДК.

## Що потрібно зробити

### Крок 1 — Додати топік `trade` у таксономію

**Файли:** `harvester/classify/taxonomy.py`, `harvester/discovery/querygen.py`

```python
# taxonomy.py — TOPICS_SEED
{
    "code": "trade",
    "name_uk": "Підприємництво, торгівля та біржова діяльність",
    "name_en": "Entrepreneurship, Trade and Exchange Activity",
    "udc": ["334.7", "334.72", "339.1", "339.13", "339.5", "336.76"],
    "kw_uk": ["підприємництво", "підприємець", "торгівля", "біржа",
              "підприємницька діяльність", "зовнішньоекономічна",
              "комерційна діяльність", "бізнес-план", "стартап",
              "малий бізнес", "біржова справа", "ринок цінних паперів"],
    "kw_en": ["entrepreneurship", "trade", "exchange", "startup",
              "small business", "commercial activity", "business plan",
              "stock exchange", "securities market"],
}
```

### Крок 2 — Міграція існуючих документів

Після додавання топіку `trade` потрібна одноразова SQL-міграція, щоб
документи з відповідними УДК отримали запис у `document_topics`:

```sql
INSERT INTO document_topics (document_id, topic_id, score, signals)
SELECT d.id, t.id, 0.45, '{"S1:trade": 0.45}'
FROM documents d, topics t
WHERE t.code = 'trade'
  AND d.status = 'verified'
  AND (d.udc LIKE '334.7%' OR d.udc LIKE '339.1%'
       OR d.udc LIKE '339.3%' OR d.udc LIKE '339.5%'
       OR d.udc LIKE '336.76%')
ON CONFLICT (document_id, topic_id) DO NOTHING;
```

Це додасть ~857 документів до топіку `trade` без повторної класифікації
через LLM.

### Крок 3 — CLI-команда `catalog`

**Файл:** `harvester/cli.py`

```
harvester catalog --topic trade [--lang uk] [--type article|book|thesis|all]
                  [--limit 30] [--output catalog.csv]
```

Логіка:
1. SELECT з `documents` JOIN `document_topics` WHERE topic = trade
2. Фільтри: language, doc_type, title IS NOT NULL (якісні записи)
3. Сортування: year DESC, потім за наявністю publisher/doi
4. Вивід: таблиця (Rich) або CSV/JSONL

### Крок 4 — Покращення якості метаданих

Для 634 записів без title потрібен re-verify (повторне завантаження PDF та
витяг метаданих). Це окрема задача, яка не блокує створення каталогу —
каталог просто фільтрує записи з title IS NOT NULL.

## Обмеження та ризики

1. **Низька якість метаданих** — 74% записів без title. Каталог зможе
   показати лише 223 повних записи (або менше, якщо додати фільтр за
   publisher).

2. **Монотипність** — 99.9% записів це статті. Для студентських робіт
   потрібні також підручники, монографії, методички. Вони або не збиралися,
   або мають інші УДК.

3. **Автоматичне оновлення** — після додавання топіку `trade` нові документи
   будуть автоматично класифіковані classify worker'ом. Але для вже зібраних
   потрібна міграція (крок 2).

4. **Конфлікт з `econ`** — документи з УДК 334.7/339.1/336.76 потрапляють
   і в `econ` (УДК 33), і в `trade`. Це нормально — document_topics
   підтримує багатотемність (max_topics=3 за замовчуванням).
