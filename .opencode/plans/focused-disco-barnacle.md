# Plan: Каталог реферативних джерел з технології пошиття чоловічого пальта

## Контекст
Потрібно створити каталог 15-30 високоякісних PDF документів для теми **"Проєктування технологічного процесу пошиття чоловічого довгого прямого пальта"**. Каталог має бути структурованим, з аналізом якості кожного документа.

### Динаміка
- Якість каталогу — головна метрика
- Пріорітет: повноцінні наукові статті → технічні документи → описи → інтернет-статті → дипломи
- Відкидати: презентації (низький пріоритет), уривки, анотації, неструктуровані PDF

## Етапи

### 1. Налаштування середовища (робота з від TMDnRPE6pWBx1, інтеграція з контекстом)
- [x] Перевірити робочу директорію `/opt/harvester`

  - `pymupdf` — для роботи з PDF (fitz)

### 2. Збір документів з різних джерел (див. доп. контекст)
Використовувати пошук документів через:
- Google Scholar / академічні пошуковики
- Відкриті репозитарії університетів (КНУТД, ХНУabi, ДНУ붓к тощо)
- Наукові журнали України (з УДК в галузі одягу/текстилю)

Потенційні пошукові запити:

- "конструювання одягу розкрій крій Україна filetype:pdf"
- "пальто пошиття технологія виготовлення Ukraine filetype:pdf"
- "наукові роботи шва courtefile.pdf"
- "дипломна робота технологія швейного виробництва filetype:pdf"

### 3. Створення PDF quality analyzer (pdf_quality.py)
Написати скрипт `/opt/harvester/harvester/verify/pdf_quality.py` який:
- Приймає шлях до PDF файлу
- Аналізує PDF з точки зору якості документа для бібліотеки

**Основні критерії аналізу:**

1. **Тип документа** (детекція через метадані, структуру, текст):
   - Наукова стаття (найвищий пріоритет)
   - Технічний документ/опис (високий)
   - Інтернет-стаття (середній)
   - Есе/огляд (середній)
   - Дипломна робота/Пояснювальна записка (середній-низький)
   - Презентація (низький — якщо немає іншого)
   - Неясний/фрагмент (відкидати)

2. **Структурні ознаки** (важливі для наукових статей):
   - Титульний аркуш з назвою, авторами, університетом/журналом
   - Вступ/Введення (Introduction)
   - Основні розділи (перевіряти заголовки розділів)
   - Висновки (Conclusion)
   - Література/References/Bibliography
   - Присутність УДК (український класифікатор)
   - Присутність Анотації/Абстракту

3. **Текстова щільність** (тільки текстовий шар PDF):
   - Розраховується сторінки з реальним текстом / загальна кількість сторінок
   - Норма: >50% сторінок мають текст — прийнятно
   - Низька щільність (багато порожніх сторінок, ілюстрацій) — нижчий пріоритет

4. **Обсяг**:
   - Мінімум 3 сторінки для статті
   - 1-2 сторінки — тільки якщо дуже щільний текст і повна структура
   - <1 сторінка — відкидати

5. **Релевантність темі**:
   - Ключові слова в тексті: пальто, швейне виробництво, технологічний процес, пошиття, конструювання, розкрій, крій, одяг, господарство, виробництво, легка промисловість

6. **Мінливість**:
   - Якщо PDF скопійований/сканований без OCR — нижчий пріоритет
   - Якщо PDF з картинок без тексту — відкидати

### 4. Класифікація документів за пріоритетами
Визначити підхід до ранжування:

| Тип | Базовий пріоритет | Мінімальні вимоги |
|-----|-------------------|-------------------|
| Наукова стаття (рецензована) | 0.9-1.0 | Титульний аркуш, УДК, Вступ, Розділи, Висновки, Література min 5 джерел |
| Наукова стаття (не рецензована) | 0.7-0.85 | Титульний аркуш, УДК, Вступ, Розділи, Висновки |
| Технічний документ (норма, стандарт) | 0.8-0.95 | Титульний аркуш, визначення, технічні вимоги |
| Інтернет-стаття (з блогу, сайту) | 0.5-0.7 | Заголовок, вступ, основна частина, висновки |
| Есе/огляд | 0.4-0.6 | Заголовок, вступ, думки, висновки |
| Диплом (ВНЗ, відкритий доступ) | 0.35-0.6 | Титульний аркуш, зміст, вступ, розділи, висновки, література |
| Презентація | 0.1-0.25 | Тільки якщо немає іншого |

### 6. Завантаження PDF (якщо ще не збережено локально)
- Використовувати `httpx` для завантаження PDF файлів
- Зберігати в `~/.harvester/catalog/resources/`
- Перевіряти інтегральність (SHA256, розмір, magic bytes %PDF)

### 7. Фінальне сортування та фільтрація
- Відфільтрувати документи з сумарним балом < 0.3
- Упорядкувати за спаданням сумарного балу
- Залишити топ-30 (або менше, якщо не має якості)

### 8. Візуальна перевірка (ручна)
- Переглянути кожен включений документ
- Переконатися що тип визначено правильно
- Виправити помилки детекції якщо потрібно

### 9. Збереження фінального каталогу
- `catalog.json` в `~/.harvester/catalog/`
- `catalog.json` в `/opt/harvester/harvester/catalog/`

## Допоміжні інструменти
- PyMuPDF (fitz) — аналіз PDF, виділення тексту, метаданих, заголовків
- httpx — завантаження PDF з інтернету
- structlog — логування процесу

## Ризики та запобігання
1. **Низька якість PDF:** Завжди перевіряти щільність тексту. Не включати документи з переважно картинками.
2. **Нерелевантні документи:** Дометовано broad пошук, треба стержняти на конкретну тему (пальто, швейне виробництво).
3. **Презентації:** Відкидати, якщо є хоча б одна стаття іншого типу. Якщо немає — включити як останній запасний варіант.
4. **Дуже короткі документи (<3 сторінки):** Ігнорувати. Виняток — статті з 2 сторінок, але з повною структурою і науковим вмістом.
5. **Презентації з вмістом:** Якщо презентація містить реальний текст, це "presentation with content" — краще виключити.
